Grown, not programmed

Engineers write the training setup of a network: the architecture, the data, the loss, and the optimizer. They do not write the algorithm the trained network ends up using. That algorithm is whatever setting of the parameters training arrived at, stored in thousands or billions of numbers. Chris Olah’s description, as quoted by Dario Amodei, is that generative AI systems are grown more than they are built.Amodei (2025), “The Urgency of Interpretability,” essay, April 2025, darioamodei.com.

One consequence is that there is no line of code to inspect for a given behavior of a trained network. In an ordinary program you can find the line that produces a behavior. In a trained network the behavior is spread over its parameters, and finding out how the network produces it is an empirical research problem, the subject of Section 6.

This page trains the same network several times from different random starting points, called seeds, and compares the results. Each run uses the same architecture, data, loss, and optimizer; only the random initial parameters differ.

The modular-addition transformer, trained five times

The transformer from Section 5.4, computing \((a + b) \bmod 59\) and trained on 30% of the pairs with weight decay 1 from five seeds, for 20,000 steps each. Each chart shows the size of each frequency in the run’s embedding at the end of training. The key frequencies, which together hold at least 90% of the embedding, are in blue and numbered.

  1. Train the five spirals networks. Will their decision boundaries be nearly the same?

    Press Train all five and look at the large plot.

    Nearly the same near the spirals, different elsewhere. Empirical finding On 2,000 new points drawn from the same spirals, any two of the five runs give the same class to between 92% and 99.8% of the points (97% on average over the ten pairs). Over the whole square, most of which holds no training points, two runs agree on as little as 77% of it (90% on average). Training constrains the boundary only near the training points.

  2. All five runs classify every training point correctly. Will the hidden units of layer 2 respond in the same way across runs?

    Compare the rows of unit pictures, then switch to layer 1.

    Some units do, most do not. Empirical finding For each layer-2 unit of one run, find the unit of another run whose responses on the 2,000 new points are most correlated with it, ignoring sign, since a unit and its negative carry the same information. Over all 60 such comparisons the median correlation is 0.78, and 42 of the 60 units have no match at 0.9 or above. The units of layer 1 are more alike: median 0.94, with 36 of the 60 matched at 0.9 or above.

  3. All five modular-addition runs answer the test pairs correctly. Will they use the same key frequencies?

    Compare the five frequency charts.

    Different frequencies. Empirical finding The five runs use frequencies 1, 12, 27; 4, 5, 15; 2, 5, 21; 15, 20, 21; and 2, 21, 22, 27. No two runs use the same set, though some frequencies recur: 21 in three runs, and 2, 5, 15, and 27 in two each. In every run, keeping only the key frequencies in the embedding leaves test accuracy at 99.9% or more, and removing them drops it to about 2%, the rate of guessing one answer in 59.

Same behavior, different internals

Both panels show the same pattern: runs that differ only in their seed reach the same behavior on the task through different internal mechanisms. Empirical finding Nanda et al. report the same for the modular-addition transformer at \(p = 113\): the key frequencies differ by seed.Nanda, Chan, Lieberum, Smith, and Steinhardt (2023), “Progress measures for grokking via mechanistic interpretability,” ICLR 2023, appendix C.2.1. The runs on this page are described in Section 5.4. Some structure does recur. Every modular-addition run here uses a few frequencies, and in image models Olah et al. found analogous features and circuits forming across different models, a claim they call universality.Olah, Cammarata, Schubert, Goh, Petrov, and Carter (2020), “Zoom In: An Introduction to Circuits,” Distill. Which mechanism a particular network uses still has to be found by examining that network.

Argument A further consequence follows. Training selects any setting of the parameters that achieves low loss, or high reward in reinforcement learning. It does not check whether the mechanism behind that setting is the one the designers had in mind, so it can select mechanisms they did not intend and would not approve of. Section 8 returns to this.

Left: a program for addition modulo \(p\). The highlighted line is the cause of one behavior, that 30 + 40 comes out as 11 when \(p = 59\). Right: the embedding matrix of the trained transformer of run 1, which computes the same function: one row for each number from 0 to 58, with 128 learned numbers in each row, positive in blue and negative in orange. The same behavior is encoded in these numbers and the model’s other parameters, and no single entry is responsible for it.

Check

Two teams train the same modular-addition transformer on the same data from different seeds, and both reach 100% test accuracy. Team A finds the key frequencies of its model. Can Team B take those to be the key frequencies of its own model?

The five runs in the panel above have the same architecture, data, and test accuracy, and no two use the same set of key frequencies. The modulus does not fix them either: all five compute addition modulo 59. Team B has to examine its own model.

Where would you look to find the rule a trained network uses for a task?

The training code and the loss say what training rewards, not which mechanism it found. The rule exists only in the trained parameters, and finding it takes investigation of the kind Section 6 describes.

Takeaway

Nobody writes the algorithm a trained network uses. Training selects parameters that achieve low loss, and the mechanism those parameters implement has to be discovered afterward. Runs that differ only in their seed can share the same behavior and differ in their internals, and training can select mechanisms nobody intended.
