Attention

A transformer keeps one vector for each position in its input, one per token. Attention is the only step in which information moves between positions. Every other step acts on each position separately.

At each position, a layer computes three vectors from the vector that position carries (its residual stream, Section 3.6): a query, which describes what the position is looking for; a key, which describes what the position offers to positions that look at it; and a value, which is what the position passes along when another position attends to it. Position \(i\) takes the dot product of its query with the key of every position \(j\) it is allowed to see, and divides each product by \(\sqrt{d_k}\), where \(d_k\) is the number of entries in each query and key vector. The results are the scores. Softmax turns the scores into attention weights: it takes the exponential of each score and divides by the sum of the exponentials, so the weights are positive and add up to 1. The attention weights are computed afresh for each input; they are not parameters. Position \(i\) receives the weighted average of the values, with these weights. In a language model, a position may attend only to itself and earlier positions; this restriction is called the causal mask. In matrix form, with one row per position,Vaswani et al. (2017), “Attention Is All You Need,” NeurIPS. Attention between two sequences was introduced earlier for translation by Bahdanau, Cho, and Bengio (2014), “Neural Machine Translation by Jointly Learning to Align and Translate,” published at ICLR 2015. For a visual introduction, see 3Blue1Brown (2024), “Attention in transformers, visually explained,” chapter 6 of the series on deep learning.

$$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}} + M\right) V,$$

where the mask \(M\) is 0 for allowed pairs and \(-\infty\) for later positions, so those get weight 0. The query, key, and value vectors come from three learned weight matrices, so what each position looks for, and what it offers, is learned in training.

Attention by hand

Four tokens, each with a query and a key in the plane, so \(d_k = 2\). Each task below asks for a prediction first. Make it, then use the tool to check it.

Queries and keys

Values and the output

Drag the tip of the selected token’s query or of any key, or select a tip with the Tab key and move it with the arrow keys. A key snaps onto another key when you bring it close. In Values and the output, the thickness of each line from the output to a value shows that value’s weight. Keys and values the selected token may not see are drawn faint.

  1. Make token 4 put a weight above 0.9 on token 2. Will it be enough to turn \(q_4\) so that it points the same way as \(k_2\), keeping its length?

    Select token 4 and turn \(q_4\) toward \(k_2\). Then make \(q_4\) longer.

    Pointing \(q_4\) along \(k_2\) at its starting length gives token 2 a weight of only about 0.64. The score is a dot product, so it grows with the lengths of the query and the key as well as with how closely they point the same way. Making \(q_4\) about twice as long, about 2.7, raises the weight above 0.9. Lengthening \(k_2\) raises the weight too, but with \(q_4\) at its starting length it stays below 0.9 everywhere in the plane (at most about 0.89).

  2. Drag \(k_3\) onto \(k_2\), so the two keys are identical. How will token 4’s weights on tokens 2 and 3 compare?

    Snap \(k_3\) onto \(k_2\), then move \(q_4\) around.

    The two weights stay equal for every \(q_4\). The weight a position receives depends only on the query and that position’s key: two positions with the same key get the same score, so the same weight, whatever their order.

  3. With the causal mask on, select token 1 and drag \(q_1\) anywhere. What weight does token 1 put on itself?

    Try it, then switch the causal mask off.

    The weight is always 1. With the mask on, token 1 may see only itself, and softmax over a single score gives weight 1, so token 1’s output is its own value whatever its query. With the mask off, token 1 can attend to later tokens; at the starting positions it puts 0.40 of its weight on token 2.

  4. Select token 4 and click Start over. If you switch the scaling off, so the scores are no longer divided by \(\sqrt{2}\), will token 4’s largest weight go up or down?

    Switch the scaling off and on, and watch row 4 of the table.

    It goes up, from 0.45 to 0.48. Without the division every score is larger in size, and the gaps between scores grow, so softmax gives more of the weight to the highest score. This always happens unless all of a token’s scores are equal.

One position, step by step

Attention for token 3 of three, computed step by step. Left: its query and the three keys. Middle: the scores \(q_3 \cdot k_j / \sqrt{2}\) are 0.91, 1.65, and −0.98, and softmax turns them into the weights 0.31, 0.65, and 0.05. Right: the output is the weighted average of the three values, so it lies between them, nearest the value of token 2.

Why the scores are divided by \(\sqrt{d_k}\)

In GPT-2 small each query and key has \(d_k = 64\) entries. If their entries are independent with mean 0 and variance 1, the dot product has variance \(d_k\), so without the division its typical size grows with \(d_k\). Large scores make softmax put almost all the weight on one position and make its gradients very small, which slows training. Dividing by \(\sqrt{d_k}\) brings the variance back to 1. Argument This is the reason Vaswani et al. suggest for the scaling.

Check

In a model with the causal mask, every position has the same key. What does position 3 receive?

Equal keys give equal scores for any query, so softmax gives equal weights to all the positions position 3 may see: 1/3 each to positions 1, 2, and 3. Position 4 is masked.

With the causal mask on, which change can make token 2’s output depend on token 3?

The mask gives token 3 a weight of exactly 0 for token 2, whatever the scores, so nothing about token 3 reaches token 2 in this layer.

Compute this one by hand. Queries and keys have \(d_k = 4\) entries. Position 2 has query \(q_2 = (1.1, 1.1, 0, 0)\); the keys are \(k_1 = (0, 0, 1, 1)\) and \(k_2 = (1, 1, 0, 0)\); the values are \(v_1 = (4, 0)\) and \(v_2 = (0, 4)\). Use \(e^{1.1} \approx 3\). What does position 2 receive?

The dot products are 0 and 2.2; divided by \(\sqrt{4} = 2\), the scores are 0 and 1.1. Softmax gives weights \(1/(1+3) = 1/4\) and \(3/4\). The output is \(\tfrac14 (4, 0) + \tfrac34 (0, 4) = (1, 3)\).

Takeaway

Attention lets each position take a weighted average of the values at the positions it may see, itself and earlier ones in a language model. The weights come from the dot products of its query with their keys, scaled by \(1/\sqrt{d_k}\) and passed through softmax: the weight on a position is high when the query’s dot product with that position’s key is large compared with its dot products with the other keys, which happens when the query and key point the same way and are long. The queries, keys, and values come from learned matrices.
