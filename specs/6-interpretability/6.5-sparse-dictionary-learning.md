## 6.5 Sparse dictionary learning

**Aim.** The reader understands sparse autoencoders (SAEs) as a method for recovering features from superposition, knows what they have found, and knows their documented limitations.

**Text (draft).**

> If each activation vector is a sum of a few feature directions out of many, we can try to recover those directions. A sparse autoencoder is trained to rebuild a layer's activations as a combination of a few directions from a large learned set, called the dictionary. It is a network with one wide hidden layer and a penalty that keeps most hidden units at zero. Ideally each hidden unit corresponds to one feature.
>
> Applied to language models, SAEs find many features that people can interpret: features for DNA sequences, Arabic text, the Golden Gate Bridge, code with security flaws, and flattering praise (Bricken et al. 2023; Templeton et al. 2024, who extracted 34 million features from Claude 3 Sonnet). A feature can be tested causally by turning it up or down (6.6).
>
> SAEs have limitations. They do not rebuild the activations perfectly, and the part they miss can matter for behavior. The features found depend on the dictionary size: a feature in a small dictionary splits into several narrower features in a larger one. On some practical tasks, SAE features have done worse than simple linear probes; in 2025 Google DeepMind's interpretability team reported such results and reduced its SAE work. Newer methods (transcoders, crosscoders, and attribution graphs) apply the same idea to trace computations across layers (6.7).

**Image.** An activation vector shown as a bar chart, decomposed into 4 active dictionary features out of 4,096, each labeled with the text snippets that activate it most.

**Interactive: "Decompose an activation".**

- Part A, live toy: an SAE trained in the browser on the hidden activations of the superposition model from 6.4. Display: rebuild error, average number of active features, and a similarity matrix between the learned dictionary and the true features. Controls: sparsity penalty, dictionary size.
- Part B, real model: a feature browser for a public SAE on GPT-2 small. Type text and see which features fire on each token; open a feature to see its top examples. Data: a subset of features and examples stored with the site.
- Try: (1) In part A, find the penalty that best recovers the true features. (2) Double the dictionary size and watch a feature split. (3) In part B, type a sentence about a bridge and find a feature for it.
- What to notice: sparsity is the lever. Too little gives codes nobody can read; too much loses information.
- Build: part A live (medium), part B precomputed (medium to large).

**Check.** Why must the dictionary be larger than the activation dimension? Answer: under superposition there are more features than dimensions.
