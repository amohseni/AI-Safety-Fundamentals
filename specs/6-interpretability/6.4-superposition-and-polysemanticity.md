## 6.4 Superposition and polysemanticity

**Aim.** The reader understands why single neurons often respond to several unrelated concepts (polysemanticity): networks represent more features than they have dimensions by giving features nearly perpendicular directions (superposition), which works when features are rarely active at the same time.

**Text (draft).**

> If each neuron represented one concept, interpretability would be easy: read the neurons. In practice many neurons are polysemantic, meaning they respond to several unrelated things. A neuron in one image model responds to cat faces, the fronts of cars, and cat legs (Olah et al. 2020). A neuron that responds to one concept is called monosemantic.
>
> Elhage et al. (2022) explained this with toy models. Suppose a network must represent n features using only m dimensions, with n larger than m. If the features are rarely active at the same time (they are sparse), the network can give each feature its own direction, with the directions overlapping slightly. The overlap causes interference only when two features are active together, which is rare. This is superposition. As sparsity rises, the toy models store more and more features, and the directions settle into regular shapes, such as five features arranged as a pentagon in two dimensions.
>
> Superposition means that the network's natural units (its neurons) are not its units of meaning (its features). A feature's direction is spread across many neurons, and each neuron takes part in many features. Section 6.5 is about recovering the features.

**Image.** Five feature directions arranged as a pentagon in a two-dimensional hidden space, with line thickness showing each feature's importance.

**Interactive: "Toy model of superposition".** One of the first eight tools to build.

- Model, trained live: n features, each active with probability 1 − S, compressed to m = 2 or 3 dimensions by a matrix W, then reconstructed with ReLU(WᵀWx + b).
- Display: the columns of W as arrows (in 2D or 3D); a heat map of WᵀW showing interference between features; bars showing which features are represented; the loss.
- Controls: n (5 to 20); m (2 or 3); sparsity S; how quickly feature importance falls off; train and reset.
- Try: (1) With S = 0 (dense features), count how many features are stored. (2) Raise S to 0.9 and watch more features squeeze in; find the pentagon. (3) Make features unequal in importance: which are dropped first? (4) Pick one hidden dimension and count how many features project onto it.
- What to notice: sparsity is what makes superposition worth its interference.
- Build: live (the model trains in seconds in the browser); medium.

**Check.** Why does superposition require sparse features? Answer: overlapping directions interfere only when several features are active at once; if that is rare, the interference costs little.

**Links.** Back to 6.2; forward to 6.5. References: Elhage et al. (2022), "Toy Models of Superposition"; Olah et al. (2020).
